## 1. USER ROLES & ACCESS CONTROL

### Roles Available
- **Superadmin** - Full system access, manage ministries, schools, users, billing
- **Ministry Admin** - Manage schools in their assigned state, view state dashboard, approve payments
- **School Admin** - Manage own school, staff, students, finances, academic records
- **Teacher** - View assigned classes, manage attendance, enter grades
- **Student** - View own profile, grades, attendance, health records
- **Parent** - View child's profile, grades, attendance, health records
- **Bursar** - Manage school finances, fees, payments, invoices

### Role-Based Navigation
- Each role should see only permitted features
- Dynamic menu/navigation based on logged-in role
- Redirect unauthorized users (403 Forbidden)

## 2. AUTHENTICATION FLOWS

### 2.1 General Login
**Endpoint:** POST /api/auth/login/
**Role:** All users
**Fields:** 
- username OR email (required)
- password (required)
**Response:**
```json
{
  "token": "abc123token",
  "user_id": 1,
  "email": "user@school.com",
  "first_name": "John",
  "last_name": "Doe",
  "role": "teacher",
  "school": {
    "id": 1,
    "name": "Lagos International School",
    "subdomain": "lagos-school-1"
  },
  "permissions": ["view_grades", "record_attendance"]
}
```
**Implementation:**
- Show login form with email/username and password fields
- Validate input before sending
- Store token securely (localStorage with HTTP-only flag if possible)
- Show error messages for invalid credentials
- Redirect to role-specific dashboard on success
- Add "Remember me" option (optional)
- Add "Forgot password" link

### 2.2 Ministry Admin Login
**Endpoint:** POST /api/auth/login/ministry/
**Role:** Ministry Admins only
**Fields:**
- email (required)
- password (required)
**Response:**
```json
{
  "token": "ministry_token_123",
  "user_id": 5,
  "email": "ministry@gov.com",
  "first_name": "Admin",
  "last_name": "Ministry",
  "role": "ministry_admin",
  "ministry": {
    "country": "Nigeria",
    "state_or_province": "Lagos",
    "currency": "NGN"
  }
}
```
**Implementation:**
- Separate login page for ministry admins
- Mark login mode as "Ministry Admin"
- Display ministry context (state, country) in dashboard after login
- All endpoints respect state-based filtering

### 2.3 Password Reset
**Endpoint:** POST /api/auth/reset-password/
**Role:** All users
**Fields:**
- email (required) - user's email
- new_password (required) - new password
- token (if sent via email) - optional
**Response:**
```json
{
  "message": "Password reset successfully"
}
```
**Implementation:**
- Password reset request form (email only)
- Backend sends reset link to email
- Reset confirmation page (token + new password)
- Show password strength indicator
- Confirm password match validation
- Show success/error message

### 2.4 Current User Profile
**Endpoint:** GET /api/auth/me/
**Role:** All authenticated users
**Response:** Current user data with role, school, permissions
**Implementation:**
- Display user profile in top navigation/sidebar
- Show current user info (name, email, role, school)
- Link to user settings/profile page

### 2.5 Logout
**Endpoint:** POST /api/auth/logout/
**Implementation:**
- Clear token from storage
- Redirect to login page
- Show logout confirmation message

## 4. SCHOOL SETUP & MANAGEMENT

### 4.1 Create School (Superadmin & Ministry Admin)
**Endpoint:** POST /api/schools/setup/
**Access:** Superadmin (any state), Ministry Admin (own state only)

**Required Fields:**
- name (string) - School name
- subdomain (string) - Unique subdomain (e.g., "lagos-school-1")
- email (string) - School email (unique)
- phone (string) - School phone number
- address (string) - Street address
- city (string) - City
- state (string) - State/Province (required, enforced)
- country (string) - Country

**Optional Fields:**
- postal_code (string)
- website (string)
- timezone (string, default: 'UTC')
- language (string, default: 'en')
- school_type (string, default: 'private')
- region (string)
- established_year (integer)
- is_active (boolean, default: True)
- primary_color (string, hex, default: '#0066CC')
- secondary_color (string, hex, default: '#FF6600')

**Validation:**
- All required fields must be filled
- Subdomain must be unique and alphanumeric
- Email must be unique and valid format
- State must match ministry admin's assigned state (if ministry admin)

**Response (201 Created):**
```json
{
  "id": 1,
  "name": "Lagos State International School",
  "subdomain": "lsis-school-1",
  "email": "admin@lsis.com",
  "phone": "08012345678",
  "address": "123 Ikoyi Road, Lagos",
  "city": "Lagos",
  "state": "Lagos",
  "country": "Nigeria",
  "postal_code": "101234",
  "website": "www.lsis.com",
  "timezone": "Africa/Lagos",
  "language": "en",
  "school_type": "private",
  "region": "Southwest",
  "established_year": 2005,
  "is_active": true,
  "primary_color": "#0066CC",
  "secondary_color": "#FF6600",
  "message": "School \"Lagos State International School\" created successfully with state \"Lagos\""
}
```

**Error Responses:**
- 400: Missing required fields
- 400: Duplicate subdomain
- 400: Duplicate email
- 403: Ministry admin trying to create school in different state
- 403: Insufficient permissions

**Implementation:**
- Form with all fields (required fields marked)
- Subdomain validation (alphanumeric, unique check)
- Email validation
- State dropdown (auto-selected for ministry admins)
- Submit button with loading state
- Success/error message display
- Redirect to school management page on success

### 4.2 School Management Page
**Endpoints:**
- GET /api/government/schools/ - List all schools (superadmin) or schools in state (ministry admin)
- GET /api/government/schools/?state=<state> - Filter by state
- GET /api/schools/<school_id>/profile/ - School details

**School Detail View:**

**School Edit Form:**

**Implementation:**

## TECHNICAL REQUIREMENTS

### Frontend Stack (Recommended)
- **Framework:** React, Vue 3, or Angular
- **Styling:** Tailwind CSS, Bootstrap, or Material UI
- **State Management:** Redux, Vuex, or Context API
- **HTTP Client:** Axios or Fetch API
- **Authentication:** JWT tokens (store securely)
- **Charts/Graphs:** Chart.js, ApexCharts, or D3.js
- **Form Handling:** React Hook Form or Formik

### API Integration Requirements
- **Base URL:** http://localhost:8000/api/ (development) or production URL
- **Authentication:** All requests (except auth) require `Authorization: Bearer <token>` header
- **Content-Type:** application/json for all POST/PUT requests
- **Error Handling:** Handle 400, 403, 404, 500 errors with user-friendly messages
- **Pagination:** Implement pagination for list endpoints (page_size=50 default)
- **Filtering:** Support filters for list endpoints (e.g., ?status=active&classroom=1)
- **Sorting:** Support sorting (e.g., ?ordering=-created_at)

### Browser Support
- Chrome (latest)
- Firefox (latest)
- Safari (latest)
- Edge (latest)
- Mobile browsers (iOS Safari, Chrome Android)

### Performance Requirements
- Page load time < 3 seconds
- API response time < 2 seconds
- Implement caching for static data
- Lazy load images and components
- Minify and compress assets

### Security Requirements
- Store JWT token securely (httpOnly cookies preferred)
- Validate all inputs before submission
- Sanitize HTML content
- Use HTTPS in production
- Implement CSRF protection
- Implement rate limiting for authentication endpoints
- Log security events

### Accessibility Requirements
- WCAG 2.1 Level AA compliance
- Keyboard navigation support
- Screen reader compatibility
- Color contrast ratios
- Alt text for images
- Form labels and error messages
